# Physical Test API

> A small, clean FastAPI service for registering users who take a physical test.

This project demonstrates a practical layered backend built with **FastAPI**, **SQLAlchemy**, **Pydantic**, and **PostgreSQL**. It validates incoming user data, prevents duplicate names, stores records in a relational database, and exposes interactive API documentation automatically.

## Features

- FastAPI endpoint for adding users
- Pydantic request and response validation
- SQLAlchemy models and repository layer
- PostgreSQL support through `psycopg`
- Business rules for valid user names and ages
- Environment-based database configuration
- Application logging in `app.log`
- Swagger UI and ReDoc generated by FastAPI

## Tech Stack

| Layer | Technology |
| --- | --- |
| API | FastAPI |
| Server | Uvicorn |
| ORM | SQLAlchemy |
| Validation | Pydantic |
| Database | PostgreSQL |
| Driver | psycopg |

## Getting Started

### 1. Clone the project

```bash
git clone <repository-url>
cd Physical-Test-Project-With-FastAPI-and-Sqlalchemy
```

### 2. Create and activate a virtual environment

Linux and macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### 3. Install dependencies

The dependency file is named `requriments.txt` in this project:

```bash
python -m pip install --upgrade pip
python -m pip install -r requriments.txt
```

### 4. Configure the database

Create a `.env` file in the project root and set a valid PostgreSQL connection string:

```env
DATABASE_URL=postgresql+psycopg://postgres:your_password@localhost:5432/physical_test
```

Make sure the PostgreSQL server is running and that the `physical_test` database already exists.

### 5. Create the database table

```bash
python create_table.py
```

### 6. Start the API

```bash
uvicorn main:app --reload
```

The service is available at `http://127.0.0.1:8000`.

## API Usage

### Add a user

`POST /add-user`

Request body:

```json
{
	"user_name": "Alex Morgan",
	"user_age": 28
}
```

Successful response:

```json
{
	"status": true,
	"message": "User successfuly added."
}
```

The endpoint accepts ages from **10 to 50**, inclusive. A blank name, an age outside that range, or a duplicate user name returns a response with `status: false` and an explanatory message.

Example with cURL:

```bash
curl -X POST "http://127.0.0.1:8000/add-user" \
	-H "Content-Type: application/json" \
	-d '{"user_name":"Alex Morgan","user_age":28}'
```

## API Documentation

With the server running, open either generated documentation page:

- Swagger UI: `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`

## Development Notes

- Keep secrets in `.env`; do not commit database passwords.
- Run commands from the project root so `.env` is discovered correctly.
- Runtime messages are written to `app.log`.
- The current table setup is intended for a simple development workflow. Use Alembic migrations before deploying schema changes to production.
